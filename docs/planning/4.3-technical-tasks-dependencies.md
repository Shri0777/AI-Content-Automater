## 3. TASK DECOMPOSITION METHODOLOGY

### 3.1 Task Hierarchy

```
Epic (EPIC-NNN)
  └── Feature (FEAT-NNN)
       └── User Story (US-NNN)
            └── Technical Task (TASK-NNN)
```

### 3.2 Task ID Convention

- **Format:** TASK-NNN (zero-padded, starting TASK-001)
- **Scope:** One task per coherent engineering deliverable
- **Size:** Neither trivial (one line) nor huge (entire subsystem)

### 3.3 Task Categories

Tasks are classified by primary responsibility:

| Category | Description | Examples |
|----------|-------------|----------|
| **Database** | Schema, migrations, constraints | Create users table, add indexes |
| **Backend** | Services, business logic, APIs | User registration service, content API |
| **Integration** | External services, providers | AI provider client, OAuth2 flow |
| **Frontend** | UI pages, forms, interactions | Login page, content editor |
| **Security** | Auth, authorization, secrets | JWT middleware, permission checks |
| **Testing** | Unit, integration, E2E tests | Auth test suite, content workflow tests |
| **DevOps** | Deployment, infrastructure | Docker setup, CI pipeline |
| **Documentation** | Technical docs, API specs | API documentation, deployment guide |

### 3.4 Task Record Format

Each task includes:

- **Task ID:** Unique identifier
- **Title:** Concise task name
- **Epic/Feature/Story:** Parent hierarchy
- **Category:** Primary classification
- **Objective:** What this task delivers
- **Technical Work:** Specific responsibilities
- **Affected Components:** System layers involved
- **Prerequisites:** Required task IDs
- **Completion Criteria:** Observable verification conditions
- **Verification Method:** How completion is validated
- **Acceptance Criteria:** Relevant AC IDs from Phase 4.2
- **Requirements:** FR/BR/NFR/UC traceability
- **Risks:** Security, failure, integration concerns
- **Blocked By:** Unresolved decisions (if any)
