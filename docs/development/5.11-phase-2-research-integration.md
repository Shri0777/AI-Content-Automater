### 4. Ranking & Deduplication Service

**Location:** `research/services/ranking.py` (406 lines)

**Purpose:** Deduplicate and rank research results with explainable scoring.

**Key Features:**

#### URL Canonicalization

Normalizes URLs for deduplication:

```python
service = RankingService()
canonical = service._canonicalize_url(url)
```

**Normalization rules:**
- Lowercase scheme and domain
- Remove `www.` prefix
- Remove trailing slashes (except root)
- Remove URL fragment (`#section`)
- Remove tracking parameters: `utm_*`, `fbclid`, `gclid`, etc.
- Keep functional parameters: `id`, `page`, etc.
- Sort query parameters for consistency

**Examples:**
```
https://www.Example.com/article?utm_source=twitter&id=123#section
→ https://example.com/article?id=123

https://example.com/page/?ref=homepage
→ https://example.com/page
```

#### Deduplication with Provenance

Groups entries by canonical URL and tracks all sources:

```python
result = service.deduplicate_and_rank(
    entries,
    query='AI tutorial',
    topics=['machine learning'],
    freshness_days=7
)
```

For duplicates:
- Selects entry with most complete metadata
- Tracks `source_count`
- Preserves `all_sources` list with provenance
- Used in corroboration scoring

#### Multi-Factor Scoring

**Configurable weights (defaults):**
```python
DEFAULT_WEIGHTS = {
    'relevance': 0.35,      # Relevance to query/topics
    'quality': 0.25,        # Source quality/credibility
    'freshness': 0.20,      # Recency
    'educational': 0.15,    # Educational value
    'corroboration': 0.05   # Independent corroboration
}
```

**Overall score calculation:**
```
overall_score = Σ (factor_score × weight)
              = relevance × 0.35
              + quality × 0.25
              + freshness × 0.20
              + educational × 0.15
              + corroboration × 0.05
```

**Individual factor algorithms:**

1. **Relevance (0-1):**
   - Keyword matching in title + summary
   - Combines query terms and topics
   - Normalized by keyword count
   - Case-insensitive

2. **Freshness (0-1):**
   - Within freshness window: 0.7-1.0 (linear decay)
   - Outside window: 0-0.7 (exponential decay)
   - Unknown date: 0.3
   - Future date: 1.0 (error handling)

3. **Quality (0-1):**
   - Baseline: 0.5
   - Has author: +0.1
   - Has publication date: +0.1
   - Long summary (>200 chars): +0.1
   - Documentation/research category: +0.15
   - News/blog category: +0.05
   - Multiple sources: +0.1

4. **Educational (0-1):**
   - Baseline: 0.5
   - Educational keywords: +0.1 each (max +0.3)
     - tutorial, guide, how to, learn, explained, etc.
   - Documentation/research category: +0.2

5. **Corroboration (0-1):**
   - 1 source: 0.0
   - 2 sources: 0.5
   - 3 sources: 0.75
   - 4+ sources: 1.0

#### Explainable Ranking

Generates human-readable rationale:

```python
entry['ranking_rationale'] = 
    "Highly relevant to query; recent content; high-quality source; 
     strong educational value; corroborated by 3 sources."
```

**Rationale components:**
- Relevance level (highly/moderately/low)
- Freshness (recent/moderately recent/older)
- Quality (high-quality/reputable/baseline)
- Educational value (if strong)
- Corroboration count (if >1 source)

## DESIGN DECISIONS

### Why Option A for Ranking Weights?

**Chosen weights:**
- Relevance: 35% — Most important (matches user intent)
- Quality: 25% — Credibility matters
- Freshness: 20% — Recent but not dominant
- Educational: 15% — Supports learning goal
- Corroboration: 5% — Bonus for multiple sources

**Rationale:**
- Relevance should dominate (users want matching content)
- Quality prevents low-value sources
- Freshness balanced with evergreen value
- Educational aligns with V3 goals
- Corroboration as tie-breaker, not requirement

**Documented as hypothesis, not scientific fact.**

### Why Separate Ranking Service?

**Benefits:**
- Testable in isolation
- Reusable across providers
- Configurable weights
- Clear separation of concerns
- Easy to tune without touching parsers

### Why preserve_from_db vs refresh_from_db?

**Decision:** Use `refresh_from_db()` in tests.

**Rationale:**
- Standard Django pattern
- Clear intent
- Handles relations correctly
