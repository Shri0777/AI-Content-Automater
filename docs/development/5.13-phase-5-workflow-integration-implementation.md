## 1. Workflow Architecture & State Machine

### 1.1 State Machine Graph & Allowed Transitions

```
[ draft ]
   │
   ▼
[ in_progress ] <──────────────────────────────────────┐
   │                                                   │
   ▼                                                   │ (Material edit / Reversion)
[ pending_review ] ──> [ draft ]                       │
   │                                                   │
   ▼                                                   │
[ approved ] ─────────> [ draft / in_progress ] ───────┤
   │                                                   │
   ▼ (Validates approval + review + platform limits)   │
[ ready_to_publish ] ─> [ approved / in_progress ] ────┘
   │
   ▼
[ published ]
   │
   ▼
[ archived ] (Terminal State)
```

| Lifecycle State | Allowed Next States | Preconditions / Quality Gates |
|---|---|---|
| `draft` | `in_progress` | Initial creation or reversion |
| `in_progress` | `pending_review`, `draft` | AI generation completes; Stage 1 review passes |
| `pending_review` | `approved`, `draft`, `in_progress` | Explicit human sign-off on specific version |
| `approved` | `ready_to_publish`, `published`, `in_progress`, `draft` | Human approved version (`is_approved=True`); Final validation passes |
| `ready_to_publish` | `published`, `approved`, `in_progress` | Platform payloads validated & prepared |
| `published` | `archived` | Platform dispatch verified |
| `archived` | *None* | Terminal state |

### 1.2 Pipeline Stage Mapping

The user-facing pipeline stepper unifies all subsystems into 5 observable stages:
1. **Research Discovery**: Collects & ranks sources from RSS/GNews via `ContentCreationRequest`.
2. **Content Generation**: Generates evidence-grounded draft with bracketed citations (`[1]`, `[2]`).
3. **AI Quality Review**: Executes Stage 1 (initial) and Stage 2 (post-correction), strictly capping automated revisions to 2 per FR-010.
4. **Human Approval Gate**: Requires explicit owner review and sign-off on the active `ContentVersion`.
5. **Publishing Preparation**: Validates character constraints (Twitter $\le 280$, LinkedIn $\le 3000$), formats attribution footnotes, and prepares target payloads.

## 2. Implemented Components

### 2.1 Database Models & Schema Extensions

1. **`Content` (`content/models.py`)**:
   - Added `ready_to_publish` to `LIFECYCLE_CHOICES`.
   - Updated `can_transition_to` and `_get_available_transitions` with strict validation rules.

2. **`PublishingPreparation` (`content/models.py`)**:
   - Tracks prepared platform payloads, target platform keys (`['twitter', 'linkedin']`), status (`prepared`, `invalidated`, `failed`), validation results, and invalidation reasons.

3. **`WorkflowAuditLog` (`content/models.py`)**:
   - Immutable audit trail (FR-021) logging security-sensitive and workflow-significant events: `state_transition`, `draft_generated`, `review_stage_1`, `review_stage_2`, `correction_applied`, `version_approved`, `approval_invalidated`, `publishing_prepared`, `validation_failed`.
   - Records actor (`user`), timestamps, `from_state`, `to_state`, and JSON event details.

4. **`ContentCreationRequest` (`research/models.py`)**:
   - Added `partial` to `STATUS_CHOICES` for partial feed/provider successes.
   - Added `error_message`, `error_type`, and `retry_count` fields for diagnostic observability.

### 2.2 Domain Services

1. **`PublishingPreparationService` (`content/services/publishing_service.py`)**:
   - **Gate Verification**: Rejects preparation if `is_approved` is False, if content is not in `approved` state, or if AI review has not passed.
   - **Deterministic Platform Validation**: Checks non-empty content ($\ge 10$ chars), verifies citations against known `ResearchContentAssociation` records (blocks hallucinated markers like `[99]`), and enforces platform character budgets (Twitter: 280, LinkedIn: 3000).
   - **Payload Formatting**: Formats compact snippets for Twitter and formatted text with source attribution footnotes for LinkedIn.
   - **Invalidation**: `invalidate_preparations_for_content` revokes active preparations whenever content undergoes material edits.

2. **`WorkflowOrchestratorService` (`content/services/workflow_orchestrator.py`)**:
   - **Concurrency Row Locking**: Wraps state transitions in `transaction.atomic()` with `select_for_update()`, preventing race conditions.
   - **Idempotency**: `approve_content_version` and `prepare_content` return existing active records on duplicate calls without redundant side-effects.
   - **Material Edit Handling**: Resets lifecycle to `in_progress`, creates immutable version with `is_approved=False`, and revokes active preparations.
   - **Dashboard Aggregation**: `get_workflow_summary` produces observable pipeline stepper metadata and recent audit events for templates.

### 2.3 User Interface & Dashboard

1. **`content/templates/content/detail.html`**:
   - **End-to-End Workflow Pipeline**: Visual stepper displaying completion status for Research, Generation, AI Review, Human Approval, and Publishing Prep.
   - **Publishing Preparation Card**: Target platform selector, final validation trigger, live platform payload preview cards with character counters and truncation warnings.
   - **Quality Gate Lock Notice**: Amber banner alerting users when publishing preparation is locked due to missing human approval.
   - **Workflow Audit Trail**: Expandable event list detailing timestamps, actions, and actors.

2. **`content/views.py` & `content/urls.py`**:
   - Added `content:prepare_publishing` (`POST /content/<id>/prepare-publishing/`).
   - Enhanced `content:transition` with dual-mode support: HTML form redirection and JSON API payloads (`application/json`).
   - Integrated `WorkflowOrchestratorService` across edit, approval, review, and transition workflows.
